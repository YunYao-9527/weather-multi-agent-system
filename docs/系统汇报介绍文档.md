# 强对流预警多智能体系统汇报介绍文档

## 一句话介绍
这是一个面向预报业务的强对流预警辅助系统：把“多源产品查看 + 人工研判 + 风险提示 + 复盘追溯”做成一体化智能体工作台，帮助预报员更快、更稳地做出判断。

## 1. 我们在解决什么问题
- 人工研判需要同时看模式、雷达、客观概率、历史经验，信息量大、切换频繁。
- 不同产品之间经常出现分歧，预报员需要额外时间做一致性判断。
- 传统流程“看得见过程、留不下证据”，事后复盘与评估效率低。

系统目标不是替代预报员，而是把重复性的信息整合和初判工作前置，给出“可解释、可追溯”的辅助建议。

## 2. 系统定位（汇报口径）
- 定位：辅助决策系统（不是自动官方发布系统）。
- 场景：强对流短临研判、值班辅助、复盘评估、策略演进。
- 价值：缩短研判链路、提升一致性、沉淀可复用经验。

## 3. 核心能力（面向业务）
- 多源融合：模式 + 雷达 + 客观概率 + 质量诊断统一入口。
- 多智能体协同：按“动力、环境、雷达、短临、一致性、质量”分工推理。
- 风险闸门：高冲突、低覆盖、关键源异常时自动切到“人工复核”。
- 可解释输出：不仅给结论，还给证据链、冲突项、贡献分解。
- 可复盘闭环：每次运行都有审计记录，可回放、可对比、可评估。

## 4. 系统怎么工作（汇报版流程）
1. 采集本轮城市和多源数据（模式、雷达、客观概率等）。
2. 多个业务 Agent 并行分析，输出证据卡片。
3. 融合层汇总为灾种概率，并计算证据就绪度和冲突状态。
4. 决策层执行安全闸门，输出建议动作（关注/复核/建议发布等内部动作）。
5. 自动生成审计记录，为复盘、评估和演进提供依据。

## 5. 为什么说“可信辅助”，而不是“黑盒建议”
- 概率与证据分离展示：灾种概率和证据就绪度分开看，避免误读。
- 高冲突自动降级：冲突越高，系统越保守，优先触发人工复核。
- 代理源显式标识：当数据来自低可信代理源时，前端会明确展示并降权。
- 全链条留痕：从输入字段到最终动作都有审计可追踪。

## 6. 页面与交互（汇报时可直接演示）
- 主页：实时业务推理（地图、落区、概率、证据、审计摘要）。
- 运维页：真值构建、窗口扫描、评估、演进（用于离线治理）。

## 7. 结果输出长什么样（业务可理解）
- 主导灾种概率：例如短时强降水/雷暴大风/冰雹/龙卷。
- 建议动作：清除、持续关注、人工复核、建议发布（内部动作语义）。
- 证据链：每个 Agent 的结论、置信度、来源与说明。
- 冲突诊断：哪些灾种存在分歧，分歧是否可控。

## 8. 当前可落地价值
- 值班时减少“跨产品来回看”的时间成本。
- 在复杂场景下给出统一的结构化研判框架。
- 把经验从“个人脑内”转为“系统可复盘资产”。

## 9. 系统边界（汇报中必须明确）
- 这是辅助系统，不是官方自动发布系统。
- 在数据异常、冲突高、覆盖不足场景下，系统默认保守并要求人工复核。
- 结论用于辅助预报员，不替代业务规程和审批流程。

## 10. 对外沟通建议话术（可直接读）
- “我们不是做一个替代预报员的黑盒模型，而是做一个能看懂、能追溯、能持续优化的预报辅助系统。”
- “系统最重要的不是给出更激进的发布建议，而是在高不确定性时明确提示风险并把人工复核拉进流程。”
- “每次输出都能回放，能知道为什么这么判断，这对业务可信和复盘治理非常关键。”
